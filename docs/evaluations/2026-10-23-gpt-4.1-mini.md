# Beyond90: GPT-4.1-mini context evaluation

Date: 23 October 2026. Deployment and response model: `gpt-4.1-mini` on Azure Foundry. The response did not identify a dated model snapshot.

## Decision

**The scoped context is an improvement, but this prompt/model/output-contract combination did not meet the predefined acceptance criteria.** Keep it experimental. Do not interpret an `AZURE AI` label or an accepted JSON response as a factual-quality guarantee.

This result does not establish that a larger model would fix the problem: no larger model was tested. A useful next change is to have the backend supply evidence IDs and numbers deterministically, while the model only writes bounded prose from selected facts. Then repeat the evaluation on additional unseen cases before deciding whether to compare a stronger deployment.

## What changed

- Selected events now include names resolved from the fixture's player and team records, rather than just opaque IDs such as `ars-8`.
- Selected-event metrics and both-team recorded-sample totals are separate objects. The sample contains 15 events; it is not a complete 90-minute match.
- The model receives the number of passes with known outcomes (7). Six completions among these seven yield 85.7%; the eighth attempted pass has an unknown outcome.
- Missing outcomes and pressure remain `null`. No shirt numbers or player aggregate statistics are supplied.
- Instructions address missing data, scope, unsupported causality, and different audience needs.

## Protocol and results

The [protocol and rubric](../../tools/Beyond90.Evaluation/README.md) were written before inspecting live outputs. Three baseline requests use the original prompt and input contract from `752ef02` on `evt-001`, one per audience. Eighteen candidate requests cover six selections and all three audiences. All 21 requests returned HTTP 200 from Azure. No retries or replacement outputs were used.

| Check | Baseline | Scoped context |
|---|---:|---:|
| API evidence validation accepted | 3/3 | **14/18** |
| Observed player/team-total attribution error in the original regression case | 3/3 | 0/3 |
| Correct named player/team in selected-event description | Names not provided | 18/18 |
| Explicitly acknowledges unknown outcome and pressure | Not tested | 3/3 |
| Includes requested `events.selected` evidence | Not the focus | **7/18** |
| Useful audience adaptation under the rubric | Not scored | **10/18** |

The last two rows show why passing API validation is not equivalent to following all instructions. The current validator checks that supplied metric keys and values exist and match, but does not enforce every requested evidence item or validate natural-language claims.

Qualitative judgments are a Codex review of every generated response, including rejected outputs, not an independent human or football-domain evaluation. Generic advice was graded weak when it did not offer a specific review angle. These subjective usefulness scores need human calibration.

### Four rejected candidate responses

| Selection / audience | Failure |
|---|---|
| Unknown outcome / Player | `passes.attempted = 1` instead of the sample's `8` |
| Unknown outcome / Coach | Same scope/value error |
| Incomplete pass / Fan | Invented metric key `underPressure` |
| Multiple events / Coach | Selected-event counts `1, 1, 2` used under sample-wide keys whose values are `6, 8, 8` |

The API returned HTTP 422 for these four responses. They were not shown as accepted insights in the app. The runner preserved their generated text for review.

### Prose findings

- All three baseline answers assigned recorded-sample totals to a player or team. The Fan answer also combined six out of eight attempts with an 85.7% rate.
- The candidate correctly identifies Martin Ødegaard and the other named actors. It preserves unknown outcome and pressure in the missing-data case.
- Several candidate answers still introduce unnecessary aggregate statistics, sometimes leaving both-team scope to a caveat or omitting it. Some give generic advice rather than a useful audience-specific explanation.
- The multiple-event Coach answer asserts maintained possession and resilience between a pass and a shot. The data establishes neither continuity nor causality. A caveat in the same answer admits that no connection can be inferred. That response was also rejected for invalid metric values.
- Sparse synthetic data limits what any model can responsibly say about tactics or decisions. A better model cannot recover facts that were never supplied.

All generated responses and per-response review notes are in [the sanitized response record](2026-10-23-responses.json). The original local run also retains the exact synthetic input context and prompt hashes; it contains no API key and is ignored by Git.

## Limits

One sample per scenario/audience, one synthetic fixture, English responses only, no repeated runs, no independent human review, and no stronger-model comparison. The baseline covers only the original regression case, so its three answers are not a comparable six-scenario benchmark. The candidate failed the acceptance gates; no overall "quality percentage" is claimed.
