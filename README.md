# Beyond90

**The Game Doesn't End at Full Time.**

Beyond90 turns synthetic football match events into explainable statistics and audience-specific match insights. The demo focuses on Leeds United and uses real player names from the 2026/27 squads, with Arsenal, Chelsea and Liverpool as scenario opponents, but every event and statistic is invented for illustration; it is not a replay or claim about an actual match. It does not analyze video or use Premier League footage, club crests, or player images.

## Project status

Players choose an individual profile with aggregate statistics before opening a match. Coaches start with a club overview of the three tracked Leeds players. Both views support individual event insights. The backend supports Azure Foundry's Responses API with a local demo provider as the default. Live Azure connectivity must be confirmed with your own credentials. Richer replay controls are a later milestone.

## Stack

- Frontend: React, TypeScript, Vite, Tailwind CSS, SVG
- Backend: ASP.NET Core Web API (.NET 10)
- Data: synthetic JSON events using real club/player names, explicitly labeled as an illustrative scenario
- Insights: local demo responses or Azure Foundry Responses API (`gpt-4.1-mini`)

## Run locally

Start the API:

```powershell
dotnet run --project backend/Beyond90.Api
```

In Visual Studio, open `backend/Beyond90.sln`, set `Beyond90.Api` as the startup project, and run the `http` profile. Keep the API running while using the frontend.

The API serves three bundled Leeds event samples (84 events each). Reports aggregate only the tracked Leeds players; these are not complete match or season statistics. Available routes:

- `GET /api/matches` — list available matches
- `GET /api/matches/{id}` — match details, teams, players, and data-status label
- `GET /api/matches/{id}/events` — ordered synthetic events
- `GET /api/matches/{id}/metrics` — calculated match metrics
- `GET /api/matches/{id}/recap` — key moments with supporting events
- `GET /api/reports/club` — tracked Leeds player list
- `GET /api/reports?playerId=lee-5` — player overview across the scenarios; omit `playerId` for tracked club totals
- `GET /api/reports?playerId=lee-5&matchId=leeds-sim-001` — individual match statistics
- `POST /api/reports/insight` — AI review with optional `playerId`, optional `matchId`, and an `audience`
- `POST /api/insights/generate` — audience-specific demo insight for selected event IDs

The insight request body contains a `matchId`, an `eventIds` array, and an `audience` (`Player` or `Coach`). The endpoint derives metrics from the fixture and rejects unknown event IDs. Demo mode requires no external AI credentials.

### Enable Azure AI locally

1. In Visual Studio, right-click **Beyond90.Api → Manage User Secrets**.
2. Merge the following into the local secrets JSON, using your resource endpoint, actual deployment name, and API key. Do not put the key in appsettings, frontend files, Git, or chat.

```json
{
  "Foundry": {
    "Enabled": true,
    "Endpoint": "https://YOUR-RESOURCE.services.ai.azure.com/openai/v1/responses",
    "Deployment": "gpt-4.1-mini",
    "ApiKey": "YOUR-KEY"
  }
}
```

3. Restart the API using the `http` development profile, then select an event and click **Generate insight**.

User Secrets are loaded in the Development environment. The frontend never receives the key. Each click in enabled mode sends an Azure request and consumes tokens; output is capped at 400 tokens with a 30-second timeout and no automatic retries. Set `Foundry:Enabled` to `false` to return to local demo mode.

The result label is **AZURE AI**, **LOCAL DEMO**, or **DEMO FALLBACK — AI UNAVAILABLE**. The last label means the external call failed, timed out, was refused, or returned an unreadable/incomplete response. Check endpoint, deployment, key, resource availability and quota if it appears. Invalid evidence is rejected rather than displayed. Event IDs, audience and cited metric values are checked against the backend; this does not guarantee every sentence is factually correct. Match data remains synthetic even when the explanation is generated by Azure.

### Context and model quality

AI requests now resolve player/team names, preserve unknown outcomes/pressure as null, and separate selected-event metrics from the recorded sample totals across both teams. Player IDs are opaque keys, not shirt numbers. Overview reviews additionally receive backend-calculated player or club totals and per-scenario breakdowns. Event narratives still receive a compact action context without spatial decision snapshots. The pass-completion denominator explicitly excludes unknown outcomes.

The first live `gpt-4.1-mini` evaluation accepted 14/18 candidate outputs through the API evidence checks and rejected four. Qualitative review also found unsupported interpretation. This prompt/model combination has **not passed the demo acceptance criteria**; an accepted response is not proof its prose is correct. See the [evaluation report](docs/evaluations/2026-10-23-gpt-4.1-mini.md), the saved responses, and the [repeatable evaluation instructions](tools/Beyond90.Evaluation/README.md).

Start the frontend in another terminal:

```powershell
cd frontend
npm install
npm run dev
```

Open the local URL printed by Vite (usually `http://localhost:5173`). The match dashboard and its **Generate insight** control are available there.

The frontend requests match data through the Vite `/api` proxy, which expects the API at `http://127.0.0.1:5089`.

Run backend tests:

```powershell
dotnet test backend/Beyond90.sln
```

Run frontend checks:

```powershell
npm test --prefix frontend -- --run
npm run build --prefix frontend
```

## Data and safety

Player and club names identify real Premier League participants; all match events, outcomes, and statistics in the demo are synthetic and are not actual performance records. No logos, footage, or player images are included. Numbers are computed by the backend; generated insight text must refer to event IDs and verified metric evidence. API credentials belong in backend environment configuration and must never be committed. The roster reference is the Premier League 2026/27 squad list.

### Spatial decision review

Open a Leeds player match and select **Review spatial scene**. Choose a passing, shooting or carrying option to inspect the same moment and geometric assessment. Scene coverage is partial and labels are not success probabilities. See [decision integration notes](docs/backend-integration-review.md) for the data contract and calculation method. `GET /api/matches/{id}/decisions` supplies the same context used by the UI and AI.
